# Hand-written examples

The 18-case frozen evaluation set is generated by `scripts/make_demo.py`. That is reproducible, but a sceptical reviewer could reasonably ask: *does the reviewer only work on inputs from its own generator?*

These two bundles answer that question. They were written directly, with a different policy and different artifact names:

| File | Policy | Expected verdict |
|---|---|---|
| `manual_bundle.json` | VIP → priority queue, then urgent / 45-minute escalation, otherwise normal | `PASS` |
| `manual_bundle_defect.json` | Same bundle with the **workflow** threshold changed from 45 → 40 minutes | `CHANGES_REQUIRED` with a counterexample |

Neither file is produced by `scripts/make_demo.py`, and neither is in `evals/frozen/`. They are covered by `tests/test_examples.py`.

Run them:

```powershell
python -m verdict examples/manual_bundle.json --format text --no-cache
python -m verdict examples/manual_bundle_defect.json --format text --no-cache
```

The defect case is a useful live demo: the spec and Python still use 45 minutes, so the reviewer localises the fault to `workflow@w1` and returns a concrete ticket that routes to `escalation` when the requirement says it should go to `normal_queue`. Rendered copies are checked in at `reports/demo_pass.txt` and `reports/manual_defect.txt`, so GitHub shows a readable example without running anything.
