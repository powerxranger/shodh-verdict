## 4. Debugging example 1 — unit normalisation

**Deliberate fault injection.** I removed the conversion line in `to_base_units` (`verdict/programs.py`) so `hours` was treated as minutes, then ran:

```
python scripts/capture_case.py hours_equivalent debug/fault_1_unit_normalization/before.json
```

**Actual failing output** (`debug/fault_1_unit_normalization/before.json`):

```json
{"status": "CHANGES_REQUIRED",
 "summary": "3 evidenced blocker(s) across 3 finding(s).",
 "findings": ["CHANGED_THRESHOLD", "CHANGED_THRESHOLD", "CHANGED_THRESHOLD"]}
```

The case expresses the same 30-minute threshold as `0.5 hours` in the requirement and `30 minutes` everywhere else. Expected `PASS`.

**Diagnosis:** the requirement guard kept the literal `0.5` while the spec/workflow/code guards held `30`. Boundary partitions at 0.5 and 30 produced three spurious divergences. The comparison was numerically wrong, not semantically different.

**Focused fix:** restore `float(value) * UNIT_TO_MINUTES[unit]` in `to_base_units`, and refine `_unit_consistency` so only genuinely non-equivalent values (or contradictory unit declarations) raise `UNIT_MISMATCH`.

**After** (`debug/fault_1_unit_normalization/after.json`): `PASS`, 27 partitions, no findings.

**Regression test:** `tests/test_regressions.py::test_registry_fault_1_hours_are_normalised_to_minutes` (checks both the helper and the end-to-end case).

## 5. Debugging example 2 — workflow false-branch negation

**Deliberate fault injection.** I changed `compile_workflow` so the false branch conjoined the condition instead of its negation:

```
python scripts/capture_case.py pass debug/fault_2_false_branch_negation/before.json
```

**Actual failing output** (`debug/fault_2_false_branch_negation/before.json`):

```json
{"status": "CHANGES_REQUIRED",
 "summary": "3 evidenced blocker(s) across 5 finding(s).",
 "findings": ["MISSING_BRANCH", "MISSING_BRANCH", "CHANGED_THRESHOLD",
              "SCRIPT_DISAGREEMENT", "SCRIPT_DISAGREEMENT"]}
```

The unchanged base case should be `PASS`.

**Diagnosis:** both branches of every decision node accumulated the *same* positive guard, so terminal paths became mutually inconsistent and the reachable-workflow program no longer covered the input space. The structural `MISSING_BRANCH` findings were downstream noise; the root cause was the lost `NOT`.

**Focused fix:** restore `walk(node.false_next, AND(path, NOT(guard)), ...)`.

**After** (`debug/fault_2_false_branch_negation/after.json`): `PASS`, 27 partitions, no findings.

**Regression test:** `tests/test_regressions.py::test_regression_fault_2_false_workflow_branch_is_negated`.

Both fault-injection edits were reverted in the committed code; the `before`/`after` reports are the actual captured outputs, and nothing above is invented history.
